# همتایار — داشبورد یکپارچه

چهار فضای کاری فارسی، با فونت محلی وزیرمتن و یک آدرس مرورگر:

| بخش                          | مسیر                  | رفتار فعلی                                                   |
| ---------------------------- | --------------------- | ------------------------------------------------------------ |
| پردازش اسناد سازمانی         | `/documents`          | ثبت نمایشی فایل با مرکز و نوع سند                            |
| پرسش‌وپاسخ                   | `/qa`                 | پرسش، مرکز، سطح دسترسی و پاسخ نمونه                          |
| جستجو عبارت در اسناد سازمانی | `/search`             | جستجوی لفظی در TXT/Markdown ثبت‌شده با فیلتر مرکز و محرمانگی |
| پردازش کدبیس                 | `/codebase/dashboard` | همان HamtayarDemo موجود، داخل داشبورد با هشت زیرمنو          |

## نصب و اجرای سریع

Node 22 یا بالاتر لازم است. ابتدا سرور قبلی UI را با `Ctrl+C` متوقف کنید؛ سپس در PowerShell:

```powershell
cd D:\Hamtayar-GitHub\hamtayar-ui
npm ci
```

برای دموی اسناد، پرسش‌وپاسخ و جستجو، بدون سرویس خارجی:

```powershell
npm run dev
```

فقط **http://127.0.0.1:5174** را باز کنید. ورود: `demo` / `Hamtayar123!`.
این ورود امنیت واقعی یا credential سرویس نیست. با `Ctrl+C` سرور متوقف می‌شود.

## اجرای یکپارچه همراه سرویس کد

اگر محیط `CGC/HamtayarDemo` قبلاً مطابق راهنمای همان پوشه تنظیم شده است:

```powershell
.\scripts\start-demo.ps1
```

این دستور سرویس Python کد و UI اصلی را اجرا می‌کند و هنگام خروج، فقط سرویس Python ساخته‌شده توسط خودش را متوقف می‌کند. **فرانت‌اند قدیمی CGC روی ۵۱۷۳ را اجرا نکنید**؛ دیگر لازم نیست. سرویس Python روی ۸۰۰۰ پشت مسیر `/code-api` قرار می‌گیرد، اما کاربر فقط همان آدرس ۵۱۷۴ را می‌بیند.

اگر نسخه به‌روز سرویس کد از قبل در حال اجراست:

```powershell
.\scripts\start-demo.ps1 -UseExistingBackend
```

اسکریپت محیط Python، CGC، رمزها یا دیتابیس را خودکار نصب و تغییر نمی‌دهد. در نصب نخست، پیش‌نیازهای `CGC/HamtayarDemo/README.md` را آماده کنید. پس از دریافت این نسخه، backend قدیمی را Restart کنید تا اجازه مبدأ ۵۱۷۴ اعمال شود. اجرای واقعی ایندکس به CGC و دو Neo4j آماده نیاز دارد؛ سالم بودن UI به معنی آماده بودن این وابستگی‌ها نیست.

آدرس پیش‌فرض backend را می‌توانید در `.env.local` تنظیم کنید:

```powershell
Copy-Item .env.example .env.local
```

`CGC_API_TARGET` فقط مبدأ HTTP(S) محلی را می‌پذیرد. رمز یا کلید مدل را در `VITE_*` نگذارید؛ تنظیمات سرویس کد همچنان در `.env` همان HamtayarDemo ذخیره می‌شود.

## راهنمای جستجوی عبارت

1. یک فایل TXT یا Markdown با متن UTF-8 در پردازش اسناد انتخاب کنید.
2. مرکز و نوع سند (عادی / محرمانه / خیلی محرمانه) را وارد کنید و «اجرای نمایش» را بزنید.
3. در بخش جستجو، عبارت، مرکز و نوع سند را انتخاب کنید؛ نتیجه نام فایل و بخش منطبق متن را نشان می‌دهد.

جستجو واقعی **در حافظه مرورگر** انجام می‌شود؛ معادل ایندکس Qdrant یا اتصال سرویس اسناد نیست. عبارت لفظی است و تفاوت حروف بزرگ و کوچک انگلیسی نادیده گرفته می‌شود. متن محلی فقط برای فایل‌های حداکثر ۲ مگابایت آماده می‌شود؛ این سقف، محدودیت آپلود دمو نیست. PDF/DOCX و فایل‌های بزرگ‌تر ثبت نمایشی می‌شوند اما با دلیل مشخص از جستجوی محلی کنار می‌روند. محتوای HTML یا کد فایل اجرا نمی‌شود.

فهرست اسناد، متن‌های محلی، مراکز، نتایج و تاریخچه فقط در نشست حافظه‌اند و با refresh، خروج یا تغییر Demo/API پاک می‌شوند. مرکز فقط از ثبت موفق جمع می‌شود. سطح دسترسی دستی، ACL معتبر نیست و Demo ادعای اعمال مجوز واقعی ندارد. پاسخ Q&A ثابت و نمونه است.

## ساخت و بررسی

```powershell
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
npm run preview
```

پیش‌نمایش نسخه ساخته‌شده: **http://127.0.0.1:4173**؛ هر دو رابط داخل همان ساخت قرار دارند و proxy کد فعال است. برای میزبانی خارج از Vite، مسیر `/code-api` باید به backend محلی و مسیرهای SPA به `index.html` نگاشت شوند؛ پوشه `dist/code` و assetها نیز باید ارائه شوند. این تحویل انتشار عمومی ندارد.

تست مرورگر با backend ساختگی و بدون اتصال به Neo4j یا مدل:

```powershell
npx playwright install chromium
npm run test:browser
```

برای بررسی همین تست روی نسخه ساخته‌شده، در PowerShell ابتدا `$env:SMOKE_PREVIEW="1"` را تنظیم کنید؛ پس از تست با `Remove-Item Env:SMOKE_PREVIEW` آن را پاک کنید.

پورت‌های ۵۱۷۹ و ۸۱۸۷ باید برای این تست آزاد باشند. عکس‌های بررسی در `runtime/browser-check` ساخته می‌شوند. این تست اتصال واقعی CGC/Neo4j را ثابت نمی‌کند. جزئیات ساختار و وضعیت اتصال در [معماری](docs/architecture.md) و [گزارش بررسی](docs/verification.md) آمده است.
